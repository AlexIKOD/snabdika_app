## 1. Назначение приложения

Приложение — рабочий инструмент оператора для трёх задач:

1. **Работа с единой номенклатурой** — поиск материала, просмотр всех предложений поставщиков с ценами, истории цен, вариантов наименований.
2. **Обработка запроса клиента** — загрузка текста или изображения, получение списка кандидатов от AI, ручное подтверждение каждой позиции.
3. **Формирование счёта** — предпросмотр и создание счёта покупателю в «МойСклад» на основании подтверждённых позиций.

Основной принцип: **приложение ничего не рассчитывает скрыто**. Любое автоматическое решение (сопоставление, выбор поставщика, цена) видно оператору и может быть изменено до создания документа.

## 3. Контракт обмена со слоем данных

### 3.1. Общие принципы

1. Приложение не обращается к SQLite и Parquet напрямую. Единственный канал — локальный HTTP API.
2. API доступен только на `127.0.0.1`, порт выделяется динамически и передаётся приложению при запуске.
3. Формат — JSON, кодировка UTF-8. Даты — ISO 8601 (`2026-09-19T10:36:00+03:00`). Денежные значения — числа с двумя знаками после запятой (не строки).
4. Все запросы идемпотентны по `Idempotency-Key` для операций создания.
5. **Режим макета.** Приложение обязано запускаться в режиме макета (`MOCK=1`), при котором вместо реального API используется встроенный mock-сервер, реализующий тот же контракт на фикстурах. Это позволяет разрабатывать интерфейс до готовности слоя данных.

### 4.2. Запуск и жизненный цикл

1. Tauri запускает слой данных как дочерний процесс, передавая порт и путь к базе.
2. Приложение ждёт `GET /api/health` до 20 секунд. Прогресс отображается на экране запуска.
3. При недоступности — экран блокировки с кнопками «Повторить», «Открыть журнал», «Указать путь к базе».
4. При закрытии окна слой данных останавливается корректно (SIGTERM, ожидание до 5 секунд).
5. При аварийном завершении дочернего процесса приложение перезапускает его не более 3 раз, затем переходит в режим ограниченной работы (только просмотр).

### 4.3. Разделение состояния и хранилища

**Классификация хранилищ.** Веб-хранилище Tauri (localStorage, sessionStorage, IndexedDB, Cache Storage) относится к **недоверенным**: данные лежат на диске в открытом виде, доступны любому процессу пользователя и сохраняются в профиле WebView. В недоверенном хранилище допускается только неконфиденциальное состояние интерфейса.

| Тип состояния | Хранилище | Примеры | Доверенное |
|---|---|---|---|
| Серверные данные | TanStack Query, только в памяти | материалы, предложения, запросы, счёт | — |
| Состояние интерфейса | Zustand, только в памяти | выбранный экран, ширина колонок | — |
| Состояние формы | локальное, только в памяти | форма настроек, разбор позиции | — |
| Настройки интерфейса | localStorage | плотность таблиц, набор и порядок колонок, последние фильтры | нет |
| Черновики запросов клиента | **база данных** через API, статус `draft` | несохранённый запрос | да |
| Секреты | Windows Credential Manager | токен «МойСклад», ключ Gemini | да |

**Запрещено сохранять в localStorage, sessionStorage, IndexedDB и Cache Storage:**

- секреты и любые значения из Windows Credential Manager;
- содержимое запросов клиентов, включая текст и изображения;
- наименования, цены и характеристики материалов из каталога;
- данные контрагентов, суммы и результаты сопоставления.

**Запрещено** включать механизм постоянного хранения (`persist` в Zustand, сохранение кэша TanStack Query) для срезов, содержащих перечисленные данные. Разрешается постоянное хранение только среза настроек интерфейса из таблицы выше.

**Черновик запроса клиента хранится в базе данных** (таблица `requests`, статус `draft`), а не в веб-хранилище: он содержит данные клиента и удаляется безвозвратно вместе с изображениями запроса (§11, пункт 16; срок хранения — открытый вопрос §18, пункт 3). Восстановление черновика после аварийного закрытия выполняется запросом к API, а не чтением локального хранилища.

Кэширование: список материалов — 60 секунд, карточка — 30 секунд, справочники — 24 часа. При создании счёта кэш запроса инвалидируется.

### 4.4. Секреты

**Принцип: секрет не покидает доверенный контур.** Ключ Gemini и токен «МойСклад» хранятся в Windows Credential Manager и доступны только оболочке Tauri (Rust). В веб-представление секрет не передаётся ни полностью, ни частично — **включая маску с символами секрета**.

**Запись секрета:**

1. Оператор вводит значение в поле типа `password` на экране настроек.
2. Значение передаётся напрямую в оболочку командой `set_secret(key, value)`.
3. Оболочка записывает его в Credential Manager.
4. Веб-представление немедленно очищает поле ввода и состояние формы.
5. Обратно возвращается только результат: `{ "status": "stored", "updated_at": "..." }`.

**Чтение и отображение:**

1. Веб-представление запрашивает `get_secret_status(key)` и получает `{ "is_set": true, "updated_at": "19.09.2026 10:46" }`.
2. Символы секрета не передаются. В интерфейсе отображается состояние «установлен» / «не установлен» и дата изменения — без маски вида `••••1234`.
3. При запуске слоя данных оболочка передаёт секреты дочернему процессу через **стандартный ввод (stdin)**, а не через аргументы командной строки и не через переменные окружения: аргументы видны в списке процессов, переменные окружения доступны для чтения другим процессам пользователя.

**Запрещено:**

- выводить секреты в консоль, журнал приложения и журнал разработчика;
- включать секреты в тексты сообщений об ошибках и трассировки стека;
- передавать секреты в отчёты об ошибках, дампы, телеметрию и аналитику;
- сохранять секреты в файлах настроек, резервных копиях и экспортируемых данных;
- отображать любые символы секрета в интерфейсе.

**Принудительные меры (обязательны к реализации):**

1. Доступ к веб-хранилищу — только через единый модуль `storage/preferences.ts`. Прямые вызовы `localStorage.setItem`, `sessionStorage.setItem`, `indexedDB.open` в остальном коде запрещены.
2. Проверка в сборке (ESLint-правило `no-restricted-globals` / `no-restricted-syntax`): прямой вызов веб-хранилища вне разрешённого модуля делает сборку неуспешной.
3. Проверка типов: тип, описывающий значение секрета, помечается брендированным типом и не может быть присвоен полю состояния или параметру функций сериализации.
4. Автоматический тест из §15.6, выгружающий содержимое всех веб-хранилищ после полного сценария работы и проверяющий отсутствие значения секрета и его подстрок.

## 5. Дизайн-система

### 5.1. Принципы

1. **Плотность.** Оператор работает с таблицами на 90 000+ строк. Интерфейс плотный, но не тесный: базовый размер шрифта 14 px, высота строки таблицы 36 px.
2. **Один акцент.** Единственный акцентный цвет для действий. Цвет используется для смысла, а не для украшения.
3. **Числа выравниваются.** Все числовые колонки — по правому краю, моноширинные цифры.
4. **Состояние всегда видно.** Загрузка, пустота, ошибка, частичные данные — разные состояния, каждое имеет собственный вид.
5. **Ничего не скрывается.** Автоматические решения AI и выбор поставщика показываются с обоснованием.
6. **Одна тема — светлая.** Приложение существует только в светлой теме. Тёмная тема не реализуется, переключатель темы отсутствует, системная настройка `prefers-color-scheme` не учитывается. Причина: оператор работает в светлом помещении у большого монитора, а тёмная палитра для плотных таблиц с семантическими цветами требует отдельной проверки контраста всех 18 токенов и удваивает объём визуального тестирования без операционной выгоды.
7. **Секции не инвертируются.** Экран имеет одну тему целиком. Ни один блок не переключается в инвертированный режим по ходу прокрутки. Допускаются только оттенки внутри светлой семьи: `--color-bg` рядом с `--color-bg-elevated`.
8. **Запрещённые приёмы.** Неоновое свечение и внешние тени-подсветки; чистый чёрный `#000000`; градиентный текст; кастомный курсор мыши; декоративные сетки-перекрестия; скругления вне шкалы §5.5.

### 5.3. Цветовые токены

**Тема одна — светлая.** Тёмная тема не реализуется (решение зафиксировано 19.09.2026). Переключатель темы в интерфейсе отсутствует, `prefers-color-scheme` не учитывается. Все токены объявляются один раз в одном файле и нигде не переопределяются.

```css
/* Поверхности */
--color-bg:             #F6F7F9;   /* полотно приложения */
--color-bg-subtle:      #EEF0F4;   /* шапка таблицы, служебные заливки */
--color-bg-elevated:    #FFFFFF;   /* панели, таблицы, модальные окна */
--color-bg-hover:       #F2F5FA;   /* наведение на строку */
--color-bg-selected:    #E8F0FE;   /* выбранная строка */

/* Границы */
--color-border:         #E3E6EA;
--color-border-strong:  #C9CED6;

/* Текст */
--color-text:           #16191D;
--color-text-muted:     #646B78;
--color-text-disabled:  #A3A9B3;

/* Акцент */
--color-accent:         #2563EB;
--color-accent-hover:   #1D4ED8;
--color-accent-subtle:  #EFF4FF;

/* Семантика */
--color-success:        #15803D;
--color-success-subtle: #ECFDF3;
--color-warning:        #B45309;
--color-warning-subtle: #FFF7ED;
--color-danger:         #B91C1C;
--color-danger-subtle:  #FEF2F2;

/* Фокус */
--color-focus-ring:     #2563EB;
```

**Правила:**

1. **Полотно и приподнятая поверхность различаются.** `--color-bg` (`#F6F7F9`) темнее `--color-bg-elevated` (`#FFFFFF`). Совпадение этих значений запрещено: при нём граница панели исчезает, и таблица сливается с фоном приложения.
2. **Чистые значения ограничены.** `#FFFFFF` допускается только для приподнятой поверхности и для текста на акценте. `#000000` не используется нигде. Основной текст — `#16191D`.
3. **Акцент один.** `--color-accent` применяется к главному действию экрана и к активному элементу навигации. Цвета статусов из блока «Семантика» акцентами не являются и применяются только по смыслу.
4. **Контраст проверен по WCAG AA (минимум 4,5:1).** Основной текст на приподнятой поверхности — 17,6:1. Приглушённый текст на полотне — 5,0:1. Белый текст на акценте — 5,1:1. Акцент на приподнятой поверхности — 5,1:1. Семантические цвета на белом: успех 5,0:1, предупреждение 5,0:1, ошибка 6,5:1.
5. **Тени тонированы в фон.** Тень использует тёмно-синюю основу `rgba(16, 24, 40, α)`, а не чистый чёрный.

Семантика статусов сопоставления:

| Статус | Токен | Подпись |
|---|---|---|
| `matched` | success | Найдено |
| `needs_review` | warning | Требует проверки |
| `conflict` | danger | Конфликт характеристик |
| `not_found` | text-muted | Не найдено |
| `rejected` | text-muted, зачёркнуто | Отклонено |
| `price_conflict` | warning | Розница ниже закупки |
| `suspected_false_merge` | warning | Подозрение на ложное объединение |

### 5.4. Типографика

```css
--font-family: "Inter", "Segoe UI", system-ui, -apple-system, sans-serif;
--font-mono:   "JetBrains Mono", "Cascadia Mono", Consolas, monospace;

--text-xs:   12px / 16px;
--text-sm:   13px / 18px;
--text-base: 14px / 20px;
--text-lg:   16px / 24px;
--text-xl:   20px / 28px;
--text-2xl:  24px / 32px;
```

Правила:

- числовые значения и коды — `--font-mono` с `font-variant-numeric: tabular-nums`;
- наименования материалов — `--text-base`, перенос по словам, максимум 2 строки в таблице;
- заголовки экранов — `--text-xl`, полужирный;
- подписи полей и вспомогательный текст — `--text-sm`, `--color-text-muted`.

**Обоснование выбора Inter.** Руководство по визуальному вкусу (§5.10) не рекомендует Inter как шрифт по умолчанию, но допускает его при нейтральном, стандартном характере интерфейса. Здесь этот случай: русскоязычный плотный рабочий интерфейс с базовым размером 14 px и таблицами на 90 000 строк. Inter выбран по трём причинам: полное покрытие кириллицы, высокая высота строчных знаков при малом кегле, табличные цифры в комплекте. Шрифт поставляется с приложением, а не загружается из внешней сети.

**Единица типографики — пиксель, а не rem.** Масштабирование выполняется системным множителем Windows, а не изменением корневого размера, поэтому размеры заданы в пикселях.

- кнопки одного назначения имеют одинаковую ширину и высоту в пределах экрана;
- текст кнопки не переносится на вторую строку при минимальной ширине окна 1280 px.

### 5.7. Состояния экранов

Каждый экран обязан реализовать пять состояний:

| Состояние | Вид |
|---|---|
| Загрузка | скелетон структуры экрана, не спиннер по центру |
| Пусто | `EmptyState` с объяснением и действием («Запросов пока нет — создайте первый») |
| Ошибка | `ErrorState` с кодом, текстом и кнопкой повтора |
| Частичные данные | данные показаны, недоступный блок помечен отдельно |
| Готово | рабочий вид |

Отдельно: **база не сформирована** — вместо пустого списка отображается пояснение «База данных не сформирована. Импорт прайсов выполняется отдельной задачей» со ссылкой на «Состояние данных».

### 5.8. Иконки

Единый набор — **Tabler Icons** (`@tabler/icons-react`, лицензия MIT). Размер: 16 px в тексте, 20 px в кнопках, 24 px в навигации. Толщина линии — единая для всего приложения: `strokeWidth={1.5}`.

Правила:

- один набор на проект; смешивание двух библиотек в одном дереве компонентов запрещено;
- собственная отрисовка иконок из путей SVG запрещена: при отсутствии нужного знака добавляется второй набор либо знак собирается из примитивов;
- толщина линии задаётся один раз в общем компоненте-обёртке и не переопределяется на месте.

Набор заменён с Lucide на Tabler при разборе руководства по визуальному вкусу (§5.10): руководство не рекомендует Lucide по умолчанию и требует единой толщины линии, а Tabler задаёт толщину явным параметром `strokeWidth` и имеет наибольшее покрытие для плотных рабочих интерфейсов.

### 5.9. Форматирование значений

| Тип | Формат | Пример |
|---|---|---|
| Цена | 2 знака, пробел как разделитель тысяч, запятая как десятичный, суффикс `руб.` | `1 234,56 руб.` |
| Вес | до 3 знаков, суффикс `кг` | `17,5 кг` |
| Размеры | разделитель `×`, без пробелов | `9×1250×2500 мм` |
| Дата | `ДД.ММ.ГГГГ` | `19.09.2026` |
| Дата и время | `ДД.ММ.ГГГГ ЧЧ:ММ` | `19.09.2026 10:36` |

| Процент | 1 знак, запятая | `29,0 %` |
| Отсутствие цены | прочерк с подсказкой | `—` («цена не указана») |

**Ноль никогда не отображается как цена.** Это соответствует правилу: нулевая цена не является ценой.

**О прочерке.** Прочерк `—` применяется только как обозначение отсутствующего значения в ячейке таблицы и в поле, не заполненном данными. Это деловая норма русскоязычных документов, а не стилистический приём. В текстах интерфейса, заголовках, кнопках и подписях тире используется по правилам русской пунктуации.

### 5.10. Соответствие руководству по визуальному вкусу

**Назначение раздела.** Дизайн-система сверена с внешним руководством по визуальному вкусу (`taste-SKILL.md`, «Anti-Slop Frontend Skill»). Ниже зафиксировано, какие правила руководства применяются к приложению, какие не применяются и почему. Без этой фиксации невозможно отличить осознанное отклонение от пропущенного требования.

**Область применимости.** Руководство прямо ограничивает свою область: целевые страницы, портфолио, редизайны. Оно не предназначено для панелей управления, плотных рабочих интерфейсов, таблиц данных и многошаговых форм (раздел 13 руководства). Приложение состоит именно из них, поэтому руководство применяется частично, а не целиком.

**Регуляторы (фиксированные значения).** Руководство требует явно задать три регулятора. Здесь они заданы как константы и не изменяются:

| Регулятор | Значение | Обоснование |
|---|---|---|
| `DESIGN_VARIANCE` | **2** | Предсказуемая симметричная сетка. Асимметрия в рабочем интерфейсе замедляет сканирование таблиц. |
| `MOTION_INTENSITY` | **2** | Анимация только как обратная связь о состоянии: заполнение индикатора выполнения, переход цвета при наведении и нажатии. Анимации появления, параллакс, скролл-эффекты и бесконечные циклы не используются. Все переходы отключаются при `prefers-reduced-motion: reduce`. |
| `VISUAL_DENSITY` | **8** | Плотный режим. В таблицах данные разделяются линиями в 1 px, а не карточками; все числа — моноширинные. Карточки применяются только на экране карточки материала и в настройках, где группировка несёт смысл. |

**Применяемые правила:**

| Правило руководства | Где закреплено |

| Один акцентный цвет на проект, запрет «AI-фиолетового» | §5.1 п. 2, §5.3 п. 3 |

| Веб-метрики LCP, INP, CLS (раздел 6.D) | Метрики загрузки веб-страниц к десктопному приложению неприменимы. Вместо них — требования §9. |

**Осознанные отклонения от применяемых правил:**

| Правило | Отклонение | Обоснование |
|---|---|---|
| Насыщенность акцента ниже 80 % (раздел 4.2) | `#2563EB` имеет насыщенность 83 % | Контраст на белом — 5,1:1, порог AA пройден. Акцент единственный, свечения нет. Снижение до 76 % (`#1D4ED8`) делает основной цвет кнопки менее различимым на плотном экране. `#1D4ED8` сохранён как цвет наведения. |

**Отклонений от правила «не использовать Lucide» нет:** набор заменён на Tabler, см. §5.8.

## 7. Экраны

### 7.1. Главная панель

**Назначение:** состояние системы и точки входа в работу.

**Состав:**

1. **Плитки показателей** (6 штук, 3 в ряд):
   - Материалов в каталоге — значение, изменение за 7 дней;
   - Предложений поставщиков — значение, число поставщиков;
   - Запросов в работе — значение, из них требуют внимания;
   - Счетов за 7 дней — значение, сумма;
   - Материалов без цены — значение, доля;
   - Материалов без веса — значение, доля.

2. **Требует внимания** — список задач с прямыми ссылками:
   - позиции с признаком `price_conflict` (розница ниже закупки);
   - группы с признаком `suspected_false_merge`;
   - запросы в статусе `review`;
   - счета в статусе `error`;
   - материалы без веса.

3. **Последние запросы** — таблица из 5 строк: номер, дата, число позиций, статус, сумма.

4. **Последние счета** — таблица из 5 строк: номер, дата, контрагент, сумма, статус, ссылка в «МойСклад».

**Действия:** «Новый запрос», «Открыть номенклатуру», переход в раздел по клику на плитку.

**Состояния:** при пустой базе плитки показывают нули, блок «Требует внимания» — пояснение о незавершённом формировании базы.

### 7.2. Единая номенклатура

**Назначение:** основной рабочий экран. Поиск материала и сравнение цен поставщиков.

**Состав:**

1. **Панель поиска и фильтров:**
   - строка поиска с подсказкой «Код, артикул или наименование» и задержкой 300 мс;
   - фильтры: категория (дерево), поставщик, единица измерения, бренд, наличие цены, наличие веса, статус, признак;
   - переключатель «Только с ценой от 2+ поставщиков»;
   - сохранённые наборы фильтров.

2. **Таблица** (виртуализированная, до 100 000 строк):

```text
Код | Артикул | Наименование | Варианты | Ед. | Вес | Категория | Бренд
--- цены по поставщикам (группа, раскрывается) ---
Петрович: розн. | себест.
СТК Строй: розн. | закуп.
СибЭлКом: розн.
Knauf-dom: розн.
--- вычисляемые ---
Лучшая закупка | Поставщик лучшей закупки
--- ---
Обновлено | Статус | Признаки
```

Правила отображения цен:

- колонки показываются только для активных поставщиков;
- при 4+ поставщиках группа цен свёрнута в одну колонку «Цены» с числом предложений; раскрытие — в карточке;
- отсутствие цены — прочерк с подсказкой «цена не указана»;
- розничная цена ниже закупочной подсвечивается предупреждающим цветом с подсказкой «Розница ниже закупки»;
- лучшая закупка выделяется полужирным.

3. **Нижняя панель:** количество найденных, переход по страницам, размер страницы (50 / 100 / 200), переключатель плотности строк, «Экспорт в Excel» (текущая выборка), настройка колонок.

4. **Боковая панель строки** (по клику) — быстрый просмотр без перехода: наименование, 3 варианта названий, все цены, вес, категория, кнопка «Открыть карточку».

**Действия:** поиск, фильтрация, сортировка по любой колонке, изменение ширины и порядка колонок, сохранение набора колонок, выделение строк, копирование, экспорт, переход в карточку, объединение выбранных материалов.

**Производительность:** первая отрисовка ≤ 300 мс на 100 строках, прокрутка без задержек, поиск ≤ 500 мс.

**Состояния:** пустой результат — пояснение и кнопка «Сбросить фильтры»; база не сформирована — отдельное сообщение (§5.7).

### 7.3. Карточка материала

**Назначение:** полная информация о материале и его предложениях.

**Заголовок:** каноническое наименование, единица, вес, категория, признаки, кнопки «Редактировать», «Объединить», «Создать вариант названия».

**Вкладки:**

1. **Обзор** — характеристики (бренд, производитель, размеры, `attributes_json` в виде таблицы «ключ — значение»), сводка цен по поставщикам, лучшая закупка, разница между лучшей и худшей закупкой.

2. **Предложения и цены** — таблица:

```text
Поставщик | Тип цены | Код поставщика | Артикул | Наименование у поставщика |
Единица | Цена | Валюта | НДС | Наличие | Обновлено | Источник
```

Сортировка по цене внутри типа. Строки группируются по поставщику. Итоговая строка — «Лучшая закупка».

3. **Варианты названий** — таблица:

```text
Наименование | Источник | Поставщик | Код | Подтверждён | Первое появление | Последнее появление
```

Действия: подтвердить, открепить от материала, перевести в другой материал.

4. **История цен** — график по каждому предложению (спарклайн с подсказкой по точкам) и таблица изменений:

```text
Дата | Поставщик | Тип цены | Было | Стало | Изменение | Изменение % | Источник
```

Изменение подсвечивается: рост — предупреждающим, снижение — успешным.

5. **Сопоставления** — история автоматических решений: дата, запрос, кандидат, уверенность, решение оператора.

**Действия:** редактирование полей, объединение с другим материалом (с предпросмотром последствий), создание варианта названия, снятие признака, экспорт карточки.

**Состояния:** материал не найден — `ErrorState`; нет предложений — пояснение в блоке цен.

**Назначение:** справочная информация и статистика по поставщикам.

**Состав:** таблица поставщиков.

Поставщик | Активен | Предложений | С ценой | Без цены | Последний импорт | Файл-источник

**Ограничение объёма:** профиль импорта и запуск импорта в настоящей задаче **не реализуются** — экран отображает данные только для чтения, кнопки управления импортом отсутствуют и появятся в следующей задаче.

### 7.5. Запрос клиента

**Назначение:** ввод запроса и запуск сопоставления.

**Состав:**

1. **Поле текста запроса** — многострочное, поддержка вставки из буфера (`Ctrl+V`), счётчик символов, сохранение черновика.
2. **Область загрузки изображений** — перетаскивание или выбор файла, форматы JPG, JPEG, PNG, WEBP, до 10 файлов, до 10 МБ каждый. Для каждого файла: миниатюра, имя, размер, кнопка удаления.
3. **Панель параметров:** поставщик по умолчанию, тип цены по умолчанию, режим выбора поставщика (см. §7.6), признак «Искать только среди материалов с ценой».
4. **Кнопка «Найти материалы»** — активна при наличии текста или хотя бы одного изображения.
5. **Индикация процесса:** этапы «Распознавание изображения», «Извлечение характеристик», «Поиск кандидатов», «Сопоставление», с возможностью отмены.

**Действия:** ввод, загрузка, удаление файлов, запуск, сохранение черновика, очистка.

**Ошибки:** недоступность Gemini — сообщение с предложением продолжить без распознавания изображений (только текстовый поиск).

### 7.6. Сопоставление и подтверждение позиций

**Назначение:** главный экран ручного контроля. Ни одна позиция не попадает в счёт без подтверждения.

**Состав:**

1. **Левая область — исходный запрос:** текст, изображения (увеличение по клику), распознанный текст отдельным блоком с пометкой «распознано автоматически».

2. **Правая область — таблица позиций:**

```text
№ | Текст запроса | Кол-во | Ед. | Найденный материал | Поставщик | Цена | Уверенность | Статус | Действия
```

3. **Разбор позиции** (по клику строка раскрывается):

   - **Распознанные характеристики:** наименование, количество, единица, бренд, артикул, код, размеры (толщина, ширина, длина, высота, диаметр), цвет, дополнительные атрибуты.
   - **Предложенный материал:** каноническое наименование, код, артикул, категория, вес, единица.
   - **Обоснование AI:** текст причины и уверенность в виде шкалы.
   - **Все предложения поставщиков** с ценами — выбор поставщика и типа цены для этой позиции.
   - **Альтернативные кандидаты:** до 5 вариантов с уверенностью, признаком конфликта характеристик и подсветкой различий (толщина, размер, единица).
   - **Различия характеристик** между запросом и кандидатом — таблица «характеристика / в запросе / у кандидата».

4. **Выбор поставщика для позиции.** Реализуется селектор с тремя режимами, задаваемыми в настройках:

   | Режим | Поведение интерфейса |
   |---|---|
   | Ручной выбор | Селектор пуст, обязателен для каждой позиции |
   | Минимальная закупка | Предвыбран поставщик с минимальной закупочной ценой, выбор подсвечен как автоматический |
   | Поставщик по умолчанию | Предвыбран заданный поставщик, замена доступна |

   Во всех режимах фактически выбранный поставщик **показан явно** и может быть изменён до подтверждения.

5. **Действия по позиции:**

```text
Подтвердить
Выбрать другой вариант
Найти вручную
Создать вариант названия
Изменить количество
Разделить позицию
Добавить материал
Отклонить позицию
```

6. **Итоговая панель (закреплена внизу):**

```text
Позиций: 12 · Подтверждено: 9 · Требуют внимания: 3
Сумма закупки: 45 120,00 руб. · Сумма розницы: 61 340,00 руб. · Маржа: 26,4 %
[Подтвердить все совпавшие] [Сформировать счёт]
```

Кнопка «Сформировать счёт» активна только когда все позиции подтверждены или отклонены. При попытке нажать неактивную кнопку — подсказка со списком нерешённых позиций.

7. **Массовые действия:** «Подтвердить все с уверенностью выше N %» (значение настраивается, по умолчанию 95 %), «Отклонить все ненайденные».

**Правила:**

- автоматическое решение не применяется при конфликте ключевых характеристик — позиция получает статус `conflict` и требует ручного выбора;
- при расхождении розничных цен поставщиков более чем на 50 % группа помечается `suspected_false_merge` и требует подтверждения;
- изменение материала или поставщика сбрасывает признак подтверждения позиции.

### 7.7. Счёт: предпросмотр и создание

**Назначение:** контроль документа до отправки в «МойСклад».

**Состав:**

1. **Реквизиты документа:** контрагент (поиск по «МойСклад»), организация, склад, дата, валюта, ставка НДС, комментарий. Поля предзаполнены из настроек и подстановок, все изменяемы.
2. **Таблица позиций:** №, наименование, код, количество, единица, цена, скидка, НДС, сумма, поставщик, закупочная цена, маржа по строке.
3. **Итоги:** сумма без НДС, сумма НДС, сумма с НДС, сумма закупки, маржа документа, число позиций.
4. **Проверки перед созданием** — блокирующие и предупреждающие:

| Проверка | Уровень |
|---|---|
| Все позиции подтверждены | блокирующая |
| Контрагент выбран | блокирующая |
| Организация и склад выбраны | блокирующая |
| У позиции есть цена | блокирующая |
| Розничная цена ниже закупочной | предупреждение |
| Счёт по этому запросу уже создан | блокирующая, со ссылкой на существующий |
| Расхождение суммы с предыдущим предпросмотром | предупреждение |

5. **Кнопка «Создать счёт»** с подтверждением: «Будет создан счёт покупателю № … на сумму … руб. Продолжить?»
6. **Результат:** номер, дата, ссылка «Открыть в МойСклад», кнопка «Скопировать ссылку».

**Защита от дублей:** перед созданием выполняется поиск документа по внешнему идентификатору запроса. При наличии — создание блокируется, показывается ссылка на существующий документ. При ошибке API запрос сохраняется со статусом `error` и доступна повторная отправка.

---

### 7.8. Счета

**Назначение:** история созданных документов.

**Состав:** таблица `Номер | Дата | Контрагент | Позиций | Сумма | Статус | Запрос | Ссылка в МойСклад`. Фильтры по дате, статусу, контрагенту. Для записей со статусом `error` — текст ошибки и кнопка повторной отправки.

---

### 7.9. Состояние данных

**Назначение:** прозрачность источника данных.

**Состав:**

1. **База данных:** путь, размер, дата последнего изменения, версия схемы.
2. **Parquet-файлы:** имя, число строк, размер, дата обновления, версия схемы, признак целостности.
3. **Наполнение:** число материалов, предложений, вариантов названий, записей истории цен.
4. **Качество данных** (только чтение): материалов без цены, без веса, с признаком `price_conflict`, с признаком `suspected_false_merge`, дублей по нормализованному наименованию.
5. **Последние импорты:** таблица из `import_batches` — дата, поставщик, файл, строк обработано, ошибок, статус.
6. **Векторный индекс:** наличие, число записей, модель, дата построения.

**Действия:** «Обновить сведения», «Открыть папку с базой», «Экспорт отчёта о состоянии». Управление импортом отсутствует — вне объёма задачи.

### 7.10. Настройки

**Разделы:**

| Раздел | Поля |
|---|---|
| Интерфейс | плотность таблиц, число строк на странице, набор колонок каталога |
| Поставщик и цены | поставщик по умолчанию, тип цены по умолчанию, режим выбора поставщика (§7.6), порог уверенности для массового подтверждения |
| «МойСклад» | адрес API, состояние токена (кнопка «Изменить»), организация, склад, ставка НДС по умолчанию, проверка соединения |
| Gemini | состояние ключа (кнопка «Изменить»), модель распознавания, модель эмбеддингов, проверка соединения |
| Данные | путь к базе, путь к папке изображений, срок хранения изображений запросов |
| Прочее | уровень журналирования, кнопка «Удалить локальные изображения запросов» |

**Тема не настраивается.** Приложение работает только в светлой теме (§5.1 п. 6), поэтому в разделе «Интерфейс» нет выбора темы.

Все изменения применяются кнопкой «Сохранить».

**Поля секретов:**

- отображают только состояние «установлен» / «не установлен» и дату последнего изменения;
- не содержат ни одного символа сохранённого секрета, в том числе в виде маски;
- ввод нового значения выполняется по кнопке «Изменить» в поле типа `password`, которое очищается после записи и при уходе с экрана;
- сохранение выполняется командой оболочки `set_secret` (§4.4), а не через общий запрос `PUT /api/settings`;
- секреты не входят в состав объекта настроек, сохраняемого в базе данных, и не возвращаются методом `GET /api/settings`.

### 7.11. Журнал

Журнал не содержит секретов и токенов.

## 8. Ключевые сценарии

### 8.1. Сравнить цены поставщиков по материалу

1. `Ctrl+K`, ввод «плита OSB 9».
2. Список кандидатов с подсказками.
3. Выбор материала — переход в карточку.
4. Вкладка «Предложения и цены» — четыре предложения от двух поставщиков.
5. Вкладка «История цен» — динамика по каждому предложению.

Ожидаемый результат: оператор видит, что у СТК Строя закупка 640,00 руб., у Петровича 711,70 руб., и принимает решение о поставщике.

### 8.2. Обработать текстовый запрос клиента

1. `Ctrl+N` — новый запрос.
2. Вставка текста «ОСБ девятка 1250 на 2500 — 20 листов».
3. «Найти материалы» — этапы сопоставления.
4. В таблице позиций — найденный материал с уверенностью 96 %.
5. Позиция раскрыта: характеристики, обоснование, кандидаты.
6. Подтверждение позиции, выбор поставщика.
7. «Сформировать счёт» → предпросмотр → «Создать счёт».

### 8.3. Обработать запрос из изображения

1. Новый запрос, перетаскивание фотографии рукописного списка.
2. «Найти материалы» — распознавание, извлечение, сопоставление.
3. В левой области отображается изображение и распознанный текст.
4. Позиции, распознанные с низкой уверенностью, помечены `needs_review`.
5. Оператор разбирает каждую: подтверждает, выбирает другой вариант или ищет вручную.
6. После разбора всех позиций — формирование счёта.

### 8.4. Разобрать конфликт характеристик

1. Позиция «OSB 9 мм» получает статус `conflict`: кандидат имеет толщину 12 мм.
2. Позиция разворачивается, в блоке различий подсвечена строка «толщина: в запросе 9 мм, у кандидата 12 мм».
3. Оператор выбирает «Найти вручную» и подбирает материал по параметрам.
4. Выбор фиксируется, позиция переходит в `matched` и подтверждается.

### 8.5. Создать вариант названия

1. В разборе позиции оператор нажимает «Создать вариант названия».
2. В диалоге отображаются исходный текст, привязка к материалу, поставщик.
3. После подтверждения вариант добавляется к материалу со статусом «подтверждён».
4. Уведомление: «Вариант добавлен. Будет распознаваться автоматически».

### 8.6. Повторная отправка счёта после ошибки

1. Счёт в статусе `error` (недоступен API «МойСклад»).
2. В разделе «Счета» — текст ошибки и кнопка «Отправить повторно».
3. Повторная отправка использует тот же внешний идентификатор запроса — дубль не создаётся.

## 11. Безопасность

### 11.1. Секреты

1. Токен «МойСклад» и ключ Gemini хранятся в Windows Credential Manager и не сохраняются в файлах настроек, базе данных, резервных копиях и экспортируемых данных.
2. В веб-представление секреты не передаются ни полностью, ни частично — в том числе в виде маски с символами секрета. Интерфейс получает только состояние «установлен» / «не установлен» и дату изменения.
3. Запись секрета выполняется командой оболочки `set_secret`; после записи поле ввода и состояние формы очищаются.
4. При запуске слоя данных секреты передаются дочернему процессу через стандартный ввод, не через аргументы командной строки и не через переменные окружения.
5. Секреты не попадают в журнал приложения, консоль, тексты ошибок, трассировки стека, отчёты об ошибках, дампы и телеметрию.
6. Метод `GET /api/settings` не возвращает секреты; метод `PUT /api/settings` их не принимает.
7. Реализуются принудительные меры из §4.4: единый модуль доступа к веб-хранилищу, проверка в сборке, брендированный тип для значения секрета.

### 11.2. Веб-хранилище

8. localStorage, sessionStorage, IndexedDB и Cache Storage считаются недоверенным хранилищем: данные лежат на диске в открытом виде.
9. В веб-хранилище допускается только неконфиденциальное состояние интерфейса: плотность таблиц, набор и порядок колонок, последние фильтры.
10. Запрещено сохранять в веб-хранилище секреты, содержимое запросов клиентов, данные каталога (наименования, цены, характеристики), данные контрагентов, суммы и результаты сопоставления.
11. Черновики запросов клиентов хранятся в базе данных (таблица `requests`, статус `draft`), а не в веб-хранилище.
12. Постоянное хранение состояния (`persist` в Zustand, сохранение кэша TanStack Query) допускается только для среза настроек интерфейса.

### 11.3. Данные и внешние сервисы

13. Размер изображения ограничивается перед отправкой во внешний API (не более 2048 px по длинной стороне, не более 5 МБ).
14. Во внешний AI передаются только текстовые поля, необходимые для сопоставления; цены, данные поставщиков и контрагентов не передаются.
15. Проверка типа и размера загружаемых файлов (JPG, JPEG, PNG, WEBP; до 10 МБ).
16. Кнопка удаления локальных изображений запросов; удаление выполняется безвозвратно, включая записи в `request_files`.
17. Локальный API доступен только на `127.0.0.1`; порт не публикуется; запросы вне localhost отклоняются.
18. Ответы API не кэшируются средствами операционной системы и браузерного движка (`Cache-Control: no-store` для всех ответов, содержащих данные каталога или контрагентов).

## 12. Локализация

Язык интерфейса — русский. Все строки вынесены в единый файл ресурсов; в коде строк не содержится. Форматы чисел, дат и валют — русские (ГОСТ). Наименования поставщиков, материалов и категорий выводятся как в источнике, без перевода.

**Одно действие — один глагол.** Одно и то же действие называется одинаково во всём приложении: если удаление позиции называется «Удалить», то в меню, подсказке и диалоге подтверждения оно называется «Удалить», а не «Убрать» или «Стереть». Синонимы ради разнообразия запрещены: в интерфейсе это читается как несогласованность. Правило распространяется на кнопки, пункты меню, подсказки и заголовки диалогов.

## 13. Доступность

1. Полное управление с клавиатуры, включая таблицы и модальные окна.
2. Видимый индикатор фокуса на всех интерактивных элементах.
3. Контраст текста не ниже 4,5:1 (WCAG AA). Расчётные значения для светлой темы приведены в §5.3 п. 4.
4. Подписи к полям связаны с полями; иконочные кнопки имеют текстовые подписи для экранных дикторов.
5. Информация о статусе не передаётся только цветом — всегда есть текст или иконка.
6. Поддержка системного масштабирования до 150 % без потери функциональности.
7. **Проверка контраста кнопок.** Текст каждой кнопки читается на её фоне. Белый текст на белом, прозрачная кнопка без границы на фоне страницы, текст на изображении без подложки запрещены. Проверяется до сдачи экрана.
8. **Проверка контраста форм.** Поля ввода, подсказки, рамка фокуса, вспомогательный и ошибочный текст проходят порог AA относительно фона своей секции. Светлая подсказка на почти белом фоне запрещена.
9. **Подпись над полем.** Подсказка не подменяет подпись. Подпись присутствует всегда, даже когда поле заполнено.

- падение слоя данных во время работы;
- недоступность базы при запуске;
- несоответствие версии схемы;
- разрыв соединения во время сопоставления.

### 15.6. Безопасность (обязательные проверки)

1. **Проверка веб-хранилища.** Сценарий: ввод токена «МойСклад» и ключа Gemini → сохранение → перезапуск приложения → создание запроса → сопоставление → создание счёта. После сценария выгружается полное содержимое localStorage, sessionStorage, IndexedDB и Cache Storage профиля WebView. Проверяется отсутствие: значения токена, значения ключа, любых их подстрок длиной от 4 символов, заголовков `Authorization`, текста запросов клиентов, наименований и цен из каталога. Наличие любого из перечисленного — дефект уровня блокирующего.

2. **Проверка канала передачи.** Секреты не обнаруживаются в списке аргументов командной строки дочернего процесса и в его переменных окружения (проверка через средства мониторинга процессов Windows).

3. **Проверка журналов.** В журнале приложения, консоли разработчика и файлах журнала отсутствуют значения секретов и их подстроки.

4. **Проверка интерфейса.** Ни на одном экране не отображается ни один символ секрета; поля секретов содержат только состояние «установлен» / «не установлен».

5. **Проверка API.** `GET /api/settings` не возвращает секреты; `PUT /api/settings` не принимает их; ответы с данными каталога и контрагентов содержат заголовок `Cache-Control: no-store`.

6. **Проверка сборки.** Попытка прямого вызова `localStorage.setItem` вне модуля `storage/preferences.ts` приводит к ошибке сборки.

7. **Проверка очистки.** После сохранения секрета поле ввода пусто; при переходе на другой экран состояние формы не содержит введённого значения.

## 16. Критерии приёмки

Приложение считается готовым, если:

1. Запускается на Windows 10 и 11, открывает рабочий экран не дольше 3 секунд.
2. Работает при пустой и при полностью наполненной базе без ошибок.
3. Показывает каталог 100 000 материалов с виртуализацией и отзывчивой прокруткой.
4. Отображает цены каждого поставщика в отдельной колонке и не сводит их в одно значение.
5. Отображает нулевую цену как отсутствие данных, а не как цену.
6. Показывает карточку материала со всеми предложениями, вариантами названий и историей цен.
7. Принимает текстовый запрос и изображение, показывает ход распознавания.
8. Показывает по каждой позиции найденный материал, уверенность, обоснование и альтернативы.
9. Позволяет выбрать поставщика для позиции и явно показывает сделанный выбор.
10. Не позволяет сформировать счёт при наличии неподтверждённых позиций.
11. Показывает предпросмотр счёта с проверками до отправки.
12. Создаёт счёт покупателю в «МойСклад» и сохраняет ссылку на документ.
13. Не создаёт дубль при повторной отправке.
14. Восстанавливает черновик запроса после аварийного закрытия.
15. **Не хранит секреты в веб-хранилище, файлах настроек, журнале и веб-представлении.** Проверяется автоматизированно: дамп всех веб-хранилищ (`localStorage`, `sessionStorage`, `IndexedDB`, `Cache Storage`) не содержит значений секретов и их подстрок; командная строка и переменные окружения дочернего процесса не содержат секретов; журналы чистые; ни один экран не отображает ни одного символа секрета. Все семь проверок §15.6 выполняются на каждом релизном билде и входят в регрессионный набор.
16. Корректно работает при недоступности Gemini или «МойСклад», не блокируя интерфейс.
17. Работает только в светлой теме, без переключателя темы и без реакции на системную настройку; поддерживает масштабирование до 150 %.
18. Полностью управляется с клавиатуры.
19. Работает в режиме макета без реального слоя данных.

- обработка ошибок и повторная отправка;
- раздел «Счета».

### Этап 5. Доводка и поставка
