# Design System — «Снабдика»

## Назначение

Этот документ задаёт единое визуальное направление для интерфейса приложения закупок. Продукт помогает работать с каталогом материалов, заявками, счетами, контрагентами, аналитикой и журналом операций. Главные задачи интерфейса — быстро находить нужные данные, сравнивать значения и безопасно выполнять операции.

Спецификация предназначена для рабочих экранов приложения, а не для рекламного сайта. Использовать её как единый источник решений о шрифтах, цветах, размерах и состояниях компонентов.

## Референс и направление

**Основной референс — SAP Fiori, с паттернами таблиц Carbon Design System.** Для ясной навигации и визуальной сдержанности также учитывать интерфейс Linear, для оформления контролов — Primer (GitHub). Это ориентиры по качеству и организации, а не задание копировать брендинг или конкретные экраны.

Почему это подходит «Снабдике»:

- SAP Fiori рассчитан на рабочие корпоративные приложения, предлагает согласованные токены и баланс плотности данных с читаемостью.
- Carbon подробно описывает таблицы, сортировку, выбор строк, пакетные действия и компактные размеры.
- Linear показывает, как сделать навигацию и заголовки спокойными и последовательными между разделами.

Итоговое направление: светлый, нейтральный B2B-интерфейс; одна заметная синяя акцентная роль; плотные, но читаемые таблицы; ясное разделение навигации, содержимого и действий. Не использовать тёплую палитру и декоративные приёмы маркетингового Notion-сайта: они не соответствуют предметной области и конкурируют с данными.

## Принципы

1. **Данные главнее декора.** Убирать лишние линии, тени, яркие заливки и конкурирующие акценты.
2. **Одна визуальная система.** Все страницы используют одинаковые типографику, шкалу отступов, радиусы, цвета и высоты контролов.
3. **Плотность без тесноты.** Таблицы и формы эффективны на широком экране; ключевые значения не обрезаются без возможности узнать полное значение.
4. **Цвет имеет значение.** Синий — действие и фокус; зелёный, янтарный и красный — только статусы и обратная связь.
5. **Понятные состояния.** Наведение, выбор, фокус, загрузка, пустой результат, ошибка и отключённое состояние различимы не только по цвету.
6. **Русский интерфейс.** Надписи короткие, предметные и единообразные; технические идентификаторы и необработанные сообщения исключены из пользовательского текста. Единый словарь: «заявка» (не «запрос» и не «документ»), «ИИ» (не «AI»), «ложное объединение», «прайс-лист».

## Типографика

Для всего интерфейса использовать **одно основное семейство Inter**. Моноширинный JetBrains Mono оставить только для кодов, UUID и технических идентификаторов; суммы, количества и обычный текст набирать Inter с табличными цифрами. Не подключать дополнительные семейства и не использовать декоративный шрифт для заголовков.

```css
font-family: Inter, "Segoe UI", Arial, sans-serif;
```

В интерфейсе достаточно четырёх начертаний: **400** — обычный текст и значения; **500** — элементы управления и подписи; **600** — заголовки, выделенные значения и активные пункты; **700** — только редкие сильные акценты, если 600 недостаточно. Не делать жирным весь текст карточек или таблиц.

### Шкала размеров

| Размер | Начертание | Применение |
|---|---:|---|
| 12 px / 16 px | 400–500 | Вспомогательная подпись, метаданные, компактный статус |
| 14 px / 20 px | 400–600 | Таблицы, поля, кнопки, навигация, выноски |
| 16 px / 24 px | 400–600 | Основной текст и важные значения |
| 20 px / 28 px | 600 | Заголовок страницы или крупной секции |
| 24 px / 32 px | 600 | Редкий крупный показатель на обзорном экране |

Стандартный текст приложения — **14 px**, основной текст чтения — **14–16 px**. Не вводить дополнительные размеры без конкретной потребности. Денежные суммы и количества не увеличивать произвольно: выделять их весом и выравниванием. Длинные наименования должны переноситься или обрезаться с доступом к полному значению.

## Цветовые роли

Все цвета задаются семантическими токенами. Компоненты не вводят собственные почти одинаковые оттенки. Ниже — базовая светлая палитра; оттенок можно уточнить при реализации, но роль и контраст должны оставаться неизменными.

| Токен / роль | Значение | Использование |
|---|---|---|
| `canvas` | `#F7F8FA` | Общий фон приложения |
| `surface` | `#FFFFFF` | Рабочая область, карточки, меню, таблицы |
| `surface-muted` | `#F2F4F7` | Вторичные панели, шапка таблицы |
| `surface-hover` | `#F2F4F7` | Наведение |
| `surface-selected` | `#E8F0FE` | Выбранная строка или пункт |
| `border` | `#E4E7EC` | Ненавязчивые разделители; не использовать как единственную границу интерактивного контрола |
| `border-strong` | `#7A8494` | Нижняя граница шапки таблицы и усиленные разделители |
| `border-control` | `#868F9B` | Рамка полей, селектов и чекбоксов: контраст ≥ 3:1 к фону (WCAG 1.4.11) |
| `border-button` | `#D0D7DE` | Рамка вторичных кнопок и чипов: они распознаются по тексту, рамка декоративна |
| `text-primary` | `#15181D` | Заголовки и основной текст |
| `text-secondary` | `#626A78` | Подписи и дополнительный текст |
| `text-muted` | `#626A78` | Подсказки и вторичный текст; контраст проверен на светлых поверхностях |
| `text-placeholder` | `#6B7380` | Placeholder полей, ≥ 4.5:1 на белом; `text-disabled` только для отключённых контролов |
| `accent` | `#2563A6` | Основные действия, ссылки, активная навигация |
| `accent-hover` | `#1E528A` | Наведение на основное действие |
| `focus` | `#2563A6` | Сплошной контур клавиатурного фокуса 2 px; полупрозрачный ореол допустим только как дополнение |
| `success` | `#15803D` | Успешное завершение |
| `warning` | `#B45309` | Предупреждение и ожидание |
| `danger` | `#B42318` | Ошибка, опасное действие |
| `info` | `#1D4ED8` | Информационное сообщение |

Статусы используют бледный фон соответствующего тона и контрастный текст. Не применять насыщенную заливку ко всей карточке или странице. Контраст обычного текста должен соответствовать WCAG AA; фокус должен оставаться заметен на любом фоне. Цвет не является единственным способом передать состояние: показывать также текст, иконку или форму.

## Размеры и геометрия

Базовая сетка отступов — **4 px**. Основные шаги: `4, 8, 12, 16, 24, 32 px`. Внутри компактных контролов использовать 8–12 px, в карточках 16–20 px, между крупными секциями 24–32 px.

| Элемент | Размер / правило |
|---|---|
| Боковая навигация | 224–248 px; сворачиваемая при узком окне |
| Заголовок страницы | Высота по содержимому; заголовок 20 px, действия справа |
| Основное поле страницы | Гибкая ширина; таблица получает приоритет по ширине |
| Стандартная строка таблицы | 40 px |
| Компактная строка таблицы | 32 px; применять только для плотного списка |
| Шапка таблицы | Та же высота, что и строки этого режима |
| Поле ввода / селект | 36 px, радиус 6 px, рамка 1 px `--color-border-control` |
| Основная кнопка | 36 px, радиус 6 px; 32 px — в компактной панели; 28 px — в строках таблиц |
| Иконка | 14 px в кнопке, 16 px в отдельной иконке-кнопке и навигации |
| Зона нажатия | Не менее 32×32 px; 28×28 px в строках таблиц; абсолютный минимум 24×24 px (WCAG 2.5.8) |
| Радиусы | 6 px для кнопок, полей и меню, 4 px для полей внутри ячеек таблицы, 8 px для карточек и диалогов |
| Контур | Обычно 1 px; избегать двойных рамок внутри одной панели |

Не задавать всем карточкам одинаковую высоту. Высота модулей определяется содержимым; выравнивать соседние карточки по сетке, если это улучшает сравнение. Карточка — только для самостоятельной группы данных или действий. Не оборачивать таблицу в несколько вложенных карточек.

## Компоненты

### Навигация и заголовки

Боковая навигация визуально спокойнее рабочей области. Активный пункт получает лёгкую синюю подложку и акцентный текст. Заголовок страницы, контекстный путь и действия располагаются последовательно и единообразно на всех маршрутах.

### Таблицы

Таблица — основной компонент каталога, счетов и журналов. Использовать ровные колонки и единое выравнивание значений одного типа: текст слева, количества и суммы — по правому краю. Заголовки короткие и спокойные; сортировка явно обозначена. Наведение подсвечивает строку, выбор имеет отдельное состояние. Пакетная панель появляется только при выборе строк. Не использовать постоянную сетку вертикальных границ и чередование контрастных полос без необходимости.

Стандартная плотность — 40 px на строку; компактная — 32 px. Не уменьшать текст ниже 12 px. Длинные значения не должны ломать ширину соседних колонок. Для таблиц с действиями закреплять панель действий только если она нужна в длинном прокручиваемом списке.

Таблица позиций документа — рабочая поверхность, а не отчёт. Количество, цена продажи, закупка и поставщик редактируются прямо в ячейке: поле высотой 28 px с рамкой, табличные цифры, видимое состояние фокуса. Высота строки — 44 px. Парные значения объединяются в одну колонку: количество с единицей, цена продажи с маржой. Редкие данные (источники цен, обоснование сопоставления, альтернативные предложения, разделение строки) уходят в раскрытие строки, чтобы основная таблица оставалась читаемой. Действия строки — иконки в конце строки с подсказками; текстовой остаётся только кнопка подтверждения. Колонка действий закреплена у правого края при горизонтальной прокрутке.

### Карточки и показатели

Карточки метрик должны иметь одинаковые внутренние отступы и последовательность: подпись, значение, при необходимости изменение или пояснение. На одной странице использовать ограниченное число крупных показателей. Не показывать рамку и тень одновременно без функциональной причины.

### Формы и выноски

Поля имеют одинаковую высоту, подпись, отступы и состояние ошибки. Подпись располагается над полем; placeholder не заменяет подпись. Ошибка находится у соответствующего поля и объясняет, что исправить.

Выноска или баннер содержит один смысл: статус, короткое объяснение и относящееся к нему действие или закрытие. Информационная выноска — нейтральный светлый фон; успех, предупреждение и ошибка используют мягкую тематическую подложку. Не складывать несколько одинаковых сообщений в разных местах экрана.

### Диалоги и боковые панели

Использовать боковую панель для просмотра деталей элемента без потери контекста списка. Диалог оставить для подтверждения, короткой формы или обязательного выбора. Панель и диалог имеют общий радиус, заголовок, внутренний ритм и чёткую основную кнопку.

### Кнопки и иконки

Стиль контролов опирается на Primer (GitHub): рамка 1 px (`--color-border-control` у полей, `--color-border-button` у кнопок и чипов), радиус 6 px, мягкая inset-тень у полей и внешняя тень 0 1 px у кнопок, спокойный hover с усилением рамки. Фокус кнопок, чипов и чекбоксов — сплошной контур 2 px `--color-focus` с отступом 2 px; у полей — акцентная рамка плюс внутреннее кольцо 1 px того же цвета. Высота 36 px, компактный вариант 32 px. Иконка в кнопке — 14 px, отступ 6 px. Вторичная кнопка всегда с рамкой, ghost — без рамки и с заливкой только при наведении. Основная кнопка имеет внутренний световой блик сверху, чтобы не сливаться с фоном.

На одном блоке — одно основное действие. В строке таблицы, тулбаре и шапке не может быть больше одного акцентного (синего) действия: остальные — нейтральные с рамкой или ghost. Опасное действие в шапке оформляется нейтрально и окрашивается только при наведении; подтверждение всё равно запрашивается диалогом. В строке таблицы все контролы одной высоты — 28 px: поле, кнопка, иконка-кнопка и бейдж выравниваются по верхнему краю ячейки. Иконки — из одного набора, одного визуального стиля и согласованных размеров 14–16 px. Не использовать emoji вместо функциональных иконок.

## Состояния и движение

Для интерактивных элементов определить `default`, `hover`, `active`, `focus-visible`, `disabled`, `loading`, `selected`, `error` и `success` там, где они применимы. Отключённое состояние сохраняет читаемость. Загрузка не должна сдвигать соседний контент.

Переходы цвета и фона — короткие, обычно 120–180 ms. Избегать масштабирования, подпрыгивания и декоративного движения; пружинные кривые (overshoot) не используются. Учитывать `prefers-reduced-motion`. Для списков предусмотреть загрузку, пустой результат, отсутствие данных и ошибку получения данных.

## Адаптивность и доступность

Основной сценарий — desktop-рабочее место. При уменьшении ширины сворачивать навигацию и убирать второстепенные панели; таблица сохраняет приоритет по ширине и доступ к горизонтальной прокрутке, если колонки невозможно безопасно сократить. Основные действия остаются видимыми.

Все действия доступны с клавиатуры. Фокусная рамка видима. Интерактивные зоны достаточно крупные; иконка-кнопка сохраняет зону нажатия минимум 32×32 px. Подписи контролов программно связаны с контролами. Таблицы имеют понятные заголовки колонок и доступное состояние сортировки.

## Продуктовые ограничения

- Сохранять исключительно светлую тему.
- Не добавлять в интерфейс историю цен, график цен или поля ценовой динамики, если это не предусмотрено требованиями продукта.
- Секреты и ключи API не сохранять в `localStorage`, логах, пользовательском тексте или отображаемых замаскированных значениях.
- Существенный результат операции показывать пользователю в интерфейсе, а не только в консоли.
- Не показывать сырые технические идентификаторы и сообщения исключений. Ошибки для пользователя проходят через `app/src/lib/errors.ts`; подробности остаются только в блоке «Технические подробности».

## Источники и обоснование

- [SAP Fiori — Visual Design Foundations](https://www.sap.com/design-system/fiori-design-web/v1-120/foundations/visual/look-feel-and-wording) — системные токены, типографика, плотность контента и визуальные основы enterprise-приложений.
- [SAP Fiori — Typography](https://www.sap.com/design-system/fiori-design-web/v1-71/foundations/visual/typography/typography) — ограниченная шкала размеров, системный sans-serif fallback и читаемость интерфейсного текста.
- [SAP Digital Design System — Spacing](https://www.sap.com/design-system/digital/foundations/layout/spacing/) — последовательная шкала отступов для компонентов и макетов.
- [Carbon Design System — Data Table](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/specifications) — плотность строк, типографика таблиц, пакетные действия и согласование размеров.
- [Carbon Design System — Data Table Guidelines](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines) — использование таблиц для поиска и обработки записей, размещение и состояния строк.
- [Linear — UI refresh, March 2026](https://linear.app/changelog/2026-03-12-ui-refresh) — согласованные заголовки и навигация, визуально спокойная боковая панель, улучшение сканирования интерфейса.

Система является собственной спецификацией «Снабдики», основанной на применимых принципах этих источников. Конкретные значения токенов выше — проектные рекомендации для приложения, а не официальные значения SAP, Carbon или Linear.
