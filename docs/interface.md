# Интерфейс

Актуализировано 24 октября 2026 года после ввода вариантов подбора, настроек
расчёта в шапке заявки и третьего UX-аудита. Визуальные правила и токены —
в [Design.md](../Design.md), здесь — структура экранов и рабочие сценарии.

## Навигация

| Раздел | Маршрут | Назначение |
| --- | --- | --- |
| Главная панель | `/` | Счётчики каталога, заявок и счетов, блок «Требует внимания» |
| Номенклатура | `/materials` | Каталог, фильтры, карточка материала |
| Поставщики | `/suppliers` | Список поставщиков и покрытие прайсов |
| Импорт прайсов | `/imports` | Загрузка XLS/XLSX, отчёт и история |
| Заявки | `/requests` | Рабочие документы и создание счёта |
| Счета | `/invoices` | Реестр выставленных документов |
| Состояние данных | `/data-status` | SQLite, Parquet, интеграции |
| Настройки | `/settings` | Провайдер AI, секреты, цены, рабочая область |
| Журнал | `/logs` | Аудит событий |

### Номенклатура

Дерево категорий показывает полные названия с переносом строк. Выбранная
подкатегория раскрывает родительскую ветку, в том числе при открытии ссылки или
после перезагрузки. Строка материала открывает быстрый просмотр; название
доступно как кнопка клавиатурой. Escape закрывает просмотр и возвращает фокус
к исходному товару.

Текстовый поиск и фильтры ограничивают каталог; счётчик показывает число
совпадений и общее число позиций. Верхняя строка таблицы и цены поставщиков
распределяют ширину по доступной области; в компактном окне сужение ниже
минимальной читаемой ширины включает горизонтальную прокрутку. Быстрый просмотр
показывает полное наименование, категорию, свойства и предложения поставщиков.

Горячие клавиши: `Alt+1…9` — разделы, `Ctrl+K` — палитра команд, `Ctrl+N` —
создание документа, `Ctrl+/` — справка.

## Раздел «Заявки»

### Список

Показывает все рабочие документы независимо от источника: номер, клиент,
источник (Заявка / Каталог / ИИ), готовность к счёту (`N из M`), сумму,
статус и дату. Чип «Скрыть выставленные» убирает завершённые документы.
Документ со связанным счётом удалить нельзя — приложение объясняет причину.

### Создание документа

Страница `/requests/new` предлагает три способа:

1. **Распознать заявку** — текст заявки, номер (подставляется автоматически)
   и необязательное имя клиента; каждая непустая строка становится позицией.
   Имя клиента нужно только счёту: там оно подставляется в поиск контрагента.
2. **Собрать из каталога** — поиск по внутренней базе показывает, сколько
   результатов загружено и сколько найдено всего. Кнопка «Показать ещё»
   загружает следующую страницу; добавленные товары и количества остаются
   в составе. После создания количество и закупка записываются в позиции.
3. **ИИ-подбор по описанию** — тот же ввод текста без клиента; сопоставление
   запускается на экране документа.

### Позиции документа

| Колонка | Содержание |
| --- | --- |
| № | Номер строки |
| Клиент | Исходная строка заявки |
| Товар | Сопоставленный материал каталога |
| Кол-во | Количество в счёте, под ним — единица |
| Себестоимость | Полная закупка за единицу, под ней — источник; правится |
| Розница | Базовая цена продажи, под ней — маржа; правится |
| Продажа | Цена к счёту, посчитанная сервером по настройкам шапки; только чтение. Прочерк — не хватает розницы, себестоимости или количества |
| Поставщик | Предложения поставщика с типом цены: «Петрович · закупка 625,13 ₽», «Петрович · розница 585,00 ₽». Выбор подставляет обе цены |
| Статус | Статус строки и оценка сопоставления |
| Действия | Раскрытие, удаление, подтверждение |

После сопоставления строка сразу получает обе цены из прайса выбранного
поставщика: себестоимость — из лучшего предложения, розницу — из прайса того
же поставщика, если она там есть. Оператор правит цену, а не вводит её с нуля.

Раскрытие строки показывает вопросы проверки (полное пояснение модели — только
когда вопросов нет), флаги, **варианты подбора** тремя группами — «Точные
совпадения», «Возможные совпадения», «Аналоги», — предложения поставщиков,
источники цен, «Подобрать материал» и «Разделить строку». Вариант выбирается
одним кликом; аналог требует отдельного подтверждения замены. Под вариантами
видно, кто и когда выбрал вариант и каким он был по рангу. Выбор товара через
«Подобрать материал» заменяет список вариантов этой строки; исходный текст
заявки не меняется. Кнопка «Добавить из каталога» добавляет новую строку.

Подтверждение — одна кнопка: приложение сохраняет изменённые поля, затем
отправляет подтверждение и выводит ошибку валидации прямо в строке. Если
отмечены галочки, подтверждаются отмеченные строки; без галочек — только
нажатая. Строка без розницы, себестоимости или количества не подтверждается.
Правка значимого поля снимает подтверждение. Массовых кнопок «Подтвердить
> 90%», «Мин. закупка» и «Отклонить ненайденные» больше нет: решение по каждой
строке принимает оператор. Фильтр «Только требующие внимания» остался.

### Расчёт счёта в шапке заявки

Над таблицей — панель «Расчёт счёта»: режим (скидка от розницы или целевая
маржа), процент, НДС и флаг «НДС включён в цену». Это один объект настроек на
заявку. Любое изменение отправляется на сервер, который пересчитывает цену к
счёту по каждой строке и показывает итог «К счёту», а под таблицей — без НДС,
НДС, прибыль, предупреждение об убытке и список нерассчитанных строк. Базовая
розница при этом не перезаписывается, поэтому пересчёт идемпотентен, а 0 %
возвращает цены к рознице.

### Создание счёта

Кнопка «Сформировать счёт покупателю» активна, когда есть готовые строки.
Берутся выбранные строки, иначе все готовые. Перед расчётом предпросмотра нужно
выбрать продавца, склад и контрагента. Продавец и склад подставляются из
последнего созданного счёта; контрагент выбирается из списка, который
фильтруется по мере ввода в поле «Поиск клиента» (отдельной кнопки нет). Если
выбор пропущен, форма отмечает конкретное поле и переводит туда фокус. Режим
расчёта, процент и НДС в окне не меняются — они показаны для справки и берутся
из шапки заявки. Доступны дата, объединение одинаковых строк и комментарий.

## Раздел «Счета»

Реестр документов, выгруженных в «МойСклад»: номер, дата, контрагент, число
позиций, сумма, себестоимость и маржа, статус, источник. Фильтры: поиск,
контрагент, период, статус, «Только убыточные». Шторка показывает состав,
сводные показатели, ссылку в «МойСклад», повтор отправки и переход к исходному
документу. Экспорт — CSV.

Создание счёта живёт только в разделе «Заявки»; кнопка «Создать счёт» ведёт
туда в режиме каталога.

## Дизайн-система

### Контролы

| Свойство | Значение |
| --- | --- |
| Высота | 36 px; компактно 32 px; в строке таблицы 28 px |
| Радиус | 6 px; в ячейках таблицы 4 px |
| Рамка | 1 px `--color-border-control`, hover — `--color-border-control-hover` |
| Тень | inset 0 1 px 2 px у полей, 0 1 px 0 у кнопок |
| Фокус | accent-рамка и кольцо 3 px |
| Иконка в кнопке | 14 px, отступ 6 px |

Основа стиля — Primer (GitHub), адаптированная под плотность приложения.
Подробности и альтернативы — в [Design.md](../Design.md) и в
[ТЗ по визуальной системе](../.ai-factory/plans/ui-system-unification.md).

### Окрашивание действий

В шапке, тулбаре и строке таблицы — не больше одного акцентного действия.
Опасное действие в шапке нейтральное и краснеет при наведении; подтверждение
запрашивается диалогом. Действия строки нейтральные, удаление — иконка.

### Таблицы

Строка 40 px (44–52 px — таблица позиций), шапка 40 px. Числовые колонки
выровнены вправо вместе с заголовками, текст усекается с подсказкой.
Колонка действий закреплена справа. Бейджи не растягивают строку.

### Форматы

| Значение | Вид |
| --- | --- |
| Деньги | `1 234,50 ₽` |
| Процент | `18,00%` |
| Дата | `21.10.2026` |
| Дата и время | `21.10.2026, 23:39` |
| Количество | `1 250,5` |

Все значения проходят через `app/src/lib/format.ts`; прямые вызовы
`toLocaleString` в экранах не используются (исключение — CSV-экспорт).

### Доступность

Кнопки и поля имеют видимый фокус, иконки-кнопки — `aria-label`, поля связаны
с подписями. Дерево раскрывается клавиатурой, строки товаров открываются по
кнопке в названии, диалоги и быстрый просмотр закрываются по `Esc`. Это не
подтверждает полную клавиатурную доступность всех страниц и виртуализированных
таблиц.

## Ограничения

- Основной сценарий — desktop от 1280 px; мобильная вёрстка не поддерживается.
- Тёмная тема не предусмотрена: приложение объявлено светлым.
- Таблица каталога прокручивается горизонтально при 9 колонках с прайсами.
- Статус документа в списке остаётся «Черновик», пока backend не меняет статус
  заявки при подтверждении строк.
- Розница подставляется только от того поставщика, у которого взята закупка;
  если в прайсе одна цена, розницу вводит оператор.
- Скидка, которую нельзя выразить в копейках, блокирует счёт сообщением об остатке
  округления; оператор меняет процент.
