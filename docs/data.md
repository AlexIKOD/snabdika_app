# Каталог и исходные данные

Пользователь подтвердил [База_нормализации.xlsx](../База_нормализации.xlsx)
как основной исходник новой базы. Импорт файла не означает, что все его
наименования прошли нормализацию.

## Рабочий каталог после обновления 23 октября 2026

Приложение читает `database/unified_catalog/*.parquet`, преобразованный из текущего
`База_нормализации.xlsx`: 96 462 материала, 117 433 ценовых предложения,
190 021 поисковый алиас. Старый каталог сохранён в
`database/unified_catalog_backup_20261023/`.

Конвертер сопоставляет столбцы по заголовкам, включая новое поле `Код_Петрович`.
`Нормализованное` переносится без изменения; при пустом значении используется
`Исходное`. Каждая строка остаётся отдельным материалом. `Цена_закупа` становится
предложением `purchase`, `Цена_продажи` — `retail`; источник переносится из
`Источник_цен`. Дополнительные цены из `Цены_других_источников` также сохраняются.
Единица цены сохраняется в предложении, единица товара — в карточке.

Наименования поставщиков и лист `Алиасы_поставщиков` включены в поиск.
Все исходные поля сохранены в `source_json`, номер строки Excel — в `excel_row`.
Статус `Нормализовано` имеют 5 999 строк; остальные 90 463 требуют проверки.
Импорт не выполняет новую нормализацию и не объединяет строки по сходству.
При равной точности поиска нормализованные карточки с заполненными ценами
выдаются перед карточками без цен.

## Повторное преобразование

Из каталога `app`:

```powershell
python -m backend.import_normalized '../База_нормализации.xlsx' '../database/catalog_next'
$env:SNABDIKA_CATALOG_DIR = (Resolve-Path '../database/catalog_next').Path
python -m pytest backend/tests/test_workbook_catalog.py backend/tests/test_normalized_import.py -q
```

Выходной каталог должен быть новым. После проверки остановите приложение,
сохраните текущий `unified_catalog` и поставьте проверенный каталог на его место.
Отчёт `import_summary.json` содержит количество записей и SHA-256 исходника.
Excel не перезаписывается; контрольная сумма проверяется до и после преобразования.

Числовые ID стабильно вычисляются из `ID` импортного слоя или `spine:<row>`.
Используется отдельное пространство ID: сохранённые заявки со старыми ID нужно
заново сопоставить с новой базой; старые документы и связи не удаляются.
Перестановка строк при сохранении этих идентификаторов не меняет ID материала.

## Проверка актуального Excel

`backend/tests/test_workbook_catalog.py` сверяет каждую строку и обе основные
цены с исходным Excel, проверяет SHA-256 и поиск Ротбанда с ценами.
`backend/tests/test_normalized_import.py` проверяет перестановку заголовков,
код Петровича, дополнительные цены, алиасы и неизменность исходника.

## Правила нормализации

Действующий порядок задаёт [NORMALIZATION_AGENT_RUNBOOK.md](../NORMALIZATION_AGENT_RUNBOOK.md),
правила — [product-naming-ru](../.agents/skills/product-naming-ru/SKILL.md).

Канонические названия готовит агент с проверкой источников; импорт и поисковый
индекс не являются новым генератором нормализованных имён. Исторический
`PLAN.md` не следует запускать как действующий программный конвейер.
Объём и порядок нормализации оставшихся строк пока не согласованы.
