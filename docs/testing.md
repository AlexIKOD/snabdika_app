# Тестирование

Актуализировано 24 октября 2026 года. Результаты относятся к локальным
проверкам frontend и backend и не означают приёмку Windows-приложения целиком.

## Команды

Из каталога `app`:

```powershell
npm test          # 79 проверок, 19 файлов (последний прогон)
npm run lint      # eslint, 0 ошибок
npm run build     # tsc --noEmit + vite build
python -m pytest backend/tests -q   # 165 проверок, около 5,5 минут
```

`npm run build` проверяет TypeScript и собирает frontend в `app/dist`.
`npm run tauri:build` дополнительно требует MSVC toolchain.

## Backend

`python -m pytest backend/tests -q` — 165 проверок: HTTP-контракт, валидация
подтверждения, сборка и расчёт счёта, резервирование строк, повтор отправки,
восстановление после неопределённого исхода, импорт и каталог. Внешние API
подменяются управляемыми ответами; сеть не требуется.

Добавленные в октябре наборы:

| Файл | Что проверяет |
| --- | --- |
| `test_matching_quality.py` | Поиск по каталогу, варианты с классом, дедупликация модификаций, аналоги отдельной группой, подстановка цен |
| `test_request_pricing.py` | Настройки расчёта в шапке: идемпотентность, 0 % возвращает розницу, исключение строк без цен, валидация, предпросмотр читает заявку |
| `test_pricing_invariants.py` | Property-based (`hypothesis`): сумма позиций равна итогу, без НДС + НДС = итог, прибыль, остаток округления, регрессия «лишняя копейка» |
| `test_moysklad_client.py` | Клиент МойСклад переживает пустое тело ответа и разбирает код ошибки |

Один тест, `test_workbook_catalog.py::test_active_catalog_matches_every_workbook_row`,
падает: он сверяет SHA-256 книги `База_нормализации.xlsx` с манифестом импорта, а
книга изменилась после последнего импорта каталога. К коду подбора и цен это не
относится.

## Браузерная проверка

Изменения каталога и счёта проверены в Chromium на рабочей базе через dev-сервер:

- главная панель, номенклатура, карточка материала;
- импорт прайсов, заявки, создание документа, карточка заявки;
- счета, состояние данных, настройки, журнал.

Повторены сценарии: полные названия дерева на 1440×900 и 1024×768; сохранение
выбранной подкатегории после перезагрузки; открытие карточки материала через
Tab и Enter с возвратом фокуса по Escape; поиск «ВВГ» с дозагрузкой всех 1 249
результатов по 200 на страницу без дублей и с сохранением количества в
корзине; заполнение таблицей каталога доступной ширины на 1440×900 без
горизонтальной прокрутки; проверка трёх обязательных реквизитов перед
предпросмотром без отправки запроса при незаполненных полях.

Сборка и ESLint прошли. Сборка сообщает неблокирующее предупреждение Vite о
размере основного чанка. Реальный масштаб WebView2, native-окно, скринридер и
внешняя отправка счёта этим прогоном не проверялись. Backend не менялся;
последний отдельно зафиксированный backend-прогон содержал 119 тестов.

## Ограничения

- Реальная сеть с принудительным обрывом не повреждалась: таймауты, 401/403/429/5xx
  и параллельность проверяются управляемыми backend-тестами.
- Настоящие счета проверены на двух документах (№6761 и №6824); налоговые комбинации — локально.
- Релизный установщик и ручная навигация в native-окне не проверялись.
- Предупреждение Vite о размере основного чанка остаётся неблокирующим.
- Подтверждение позиции обращается к «МойСклад»; в тестах этот вызов мокируется.
