### Проверка сопоставления на примере §8 ТЗ

Из шести написаний одного материала автоматически сводятся пять:

```
Плита OSB-3 9х1250х2500 мм   ┐
Плита OSB-3  9х1250х2500 мм  │  ключ: ((3, 9, 1250, 2500), {osb})
ОСБ-3 9 мм 1250*2500         │
Плита ОСП 3 9x1250x2500      │
OSB 3 9 1250 2500            ┘
ОСБ девятка 1250 на 2500        ключ: ((9, 1250, 2500), {osb}) — НЕ сводится
```

Шестое написание отличается отсутствием класса «3» — корректно требует AI-сопоставления или ручного подтверждения (§14 ТЗ). Это подтверждает необходимость уровней 4–5 из §12.

2. **Реальные межпоставщиковые совпадения существуют, но их мало:** 244 группы из 90 033 (0,3 %). Примеры корректных срабатываний:

3. **Конфликты единиц измерения внутри групп:** 481 (0,5 %) — все требуют ручного подтверждения по §12.

## Правка 5. Модель цен: отдельные поля по поставщикам

**Разделы:** §7.1, §12.1, §13, §23.3
**Решение (19.09.2026):** цены разных поставщиков хранятся в отдельных полях и не сводятся в одно значение. Розничные цены собираются из прайсов Петровича и СТК Строя.

### 5.1. Принцип

1. Каждое предложение поставщика — отдельная запись со своей ценой. Материал хранит **набор предложений**, а не одну «текущую» цену.
2. Каждый тип цены хранится отдельно: розничная, закупочная, себестоимость, региональная.
3. Сводные показатели (минимальная закупочная цена, поставщик лучшей закупки) **вычисляются**, но не заменяют исходные значения.
4. Цена не переносится между поставщиками: цена Петровича не становится ценой СТК Строя.

### 5.2. Фактическая матрица цен (проверено на данных)

| Источник | Тип цены | Позиций | Цена > 0 | Цена = 0 | Примечание |
|---|---|---|---|---|---|
| Петрович (розница) | розничная | 55 362 | 55 362 | 0 | отдельный файл |
| Петрович (себестоимость) | закупочная | 55 438 | 55 438 | 0 | отдельный файл |
| **СТК Строй** | **розничная** | 6 647 | 5 456 | 1 191 | колонка «Цена: Цена продажи» |
| **СТК Строй** | **закупочная** | 6 647 | 3 747 | 2 900 | колонка «Закупочная цена» |
| СибЭлКом | розничная | 7 227 | 1 112 | 6 115 | цена текстом, «По согласованию» |
| Knauf-dom | розничная | 412 | 369 | 43 | колонка «Цена продажи» |

**Ключевое:** у СТК Строя присутствуют **оба типа цен** — и розничная, и закупочная; обе заполнены у 3 728 позиций из 6 647. У Петровича розница и себестоимость находятся в разных файлах и связываются по коду.

### 5.4.1. Проверка модели на полном каталоге

Этап C прототипа (`prototype/dedup_prototype.py`) формирует предложения в разрезе «поставщик × тип цены»:

| Поставщик | Тип цены | Предложений с ценой > 0 |
|---|---|---|
| Петрович | закупочная | 55 438 |
| Петрович | розничная | 55 362 |
| СТК Строй | розничная | 5 448 |
| СибЭлКом | розничная | 1 112 |
| Knauf-dom | розничная | 369 |
| **Итого** | | **117 729** |

Отброшено нулевых цен: **1 217** — это подтверждает правило 1 из §12.1: ноль не является ценой и не должен попадать в предложение. Без этого правила прототип показывал расхождение розничных цен 100 % на парах «0,00 против N руб.», что искажало анализ.

Материалов с розничной ценой от двух и более поставщиков: **175**. Медианное расхождение розничных цен — **29,0 %**, максимальное — **99,4 %**.

**Наблюдение:** расхождение свыше 50 % почти всегда означает ложное объединение разных товаров, а не реальную разницу цен. Пример: пара с расхождением 99,4 % (45,00 против 7 832,00 руб.) — это разные позиции, ошибочно сведённые по совпадению чисел и слов. Рекомендуется использовать расхождение цен как признак для ручной проверки:

```markdown
Если у материала розничные цены поставщиков расходятся более чем на 50 %,
группа помечается признаком `suspected_false_merge` и выносится оператору
на подтверждение до использования в расчётах.
```

### 5.5. Структура хранения

Внести в §16 (SQLite) следующие таблицы:

```sql
-- Поставщик
CREATE TABLE suppliers (
    supplier_id      INTEGER PRIMARY KEY,
    supplier_name    TEXT NOT NULL,          -- Петрович, СТК Строй, СибЭлКом, Knauf-dom
    price_source     TEXT,                   -- файл или папка прайса
    is_active        INTEGER NOT NULL DEFAULT 1
);

-- Тип цены
CREATE TABLE price_types (
    price_type_id    INTEGER PRIMARY KEY,
    code             TEXT NOT NULL UNIQUE,   -- retail | purchase | cost | regional
    title            TEXT NOT NULL           -- Розничная | Закупочная | Себестоимость | Региональная
);

-- Предложение поставщика: одна строка = материал x поставщик x тип цены
CREATE TABLE supplier_offers (
    offer_id         INTEGER PRIMARY KEY,
    material_id      INTEGER NOT NULL REFERENCES materials(material_id),
    supplier_id      INTEGER NOT NULL REFERENCES suppliers(supplier_id),
    price_type_id    INTEGER NOT NULL REFERENCES price_types(price_type_id),
    supplier_code    TEXT,                   -- нормализованный код поставщика
    supplier_article TEXT,
    original_name    TEXT NOT NULL,          -- наименование как в источнике
    normalized_name  TEXT NOT NULL,
    unit             TEXT,
    price            NUMERIC(14,2),          -- NULL = цена не указана («По согласованию»)
    currency         TEXT NOT NULL DEFAULT 'RUB',
    vat_rate         NUMERIC(5,2),
    availability     TEXT,
    source_file      TEXT,
    import_batch_id  INTEGER,
    price_updated_at TEXT,
    UNIQUE (material_id, supplier_id, price_type_id)
);

-- История цен: изменение фиксируется по конкретному предложению
```

### 5.9. ⚠ Открытый вопрос: выбор цены для счёта

|---|---|---|
